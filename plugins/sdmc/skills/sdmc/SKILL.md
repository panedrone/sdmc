# sdmc: data access layer from a live database

sdmc reads the metadata of a reachable database (tables, views, FKs, query result sets, procedure
parameters) and an XML manifest (`sdm.xml`), and writes plain models and DAO functions. Do not write
DAO code by hand and do not edit generated files: change `sdm.xml` and regenerate.

Reference: https://github.com/panedrone/sdmc (README), XML syntax:
https://sqldalmaker.sourceforge.net/dto-models.html and https://sqldalmaker.sourceforge.net/dao.html

## Install

```bash
sdmc version || go install github.com/panedrone/sdmc/cmd/sdmc@latest
```

Without Go: a binary from https://github.com/panedrone/sdmc/releases. `sdmc` without arguments
prints the full usage; `sdmc help init` the options of `init`.

## Workflow (Go)

Run in the folder of `go.mod` (create it first: `go mod init <module>`).

```bash
sdmc init -dir sdm -dao internal/dbal -orm no_orm -db sqlite
```

- `-orm no_orm|sqlx|gorm`, `-db pg|mysql|sqlite|mssql`. All four options are required.
  Default choice when the user said nothing: `-orm no_orm`, `-dir sdm`, `-dao internal/dbal`.
- `-dir sdm` is the default folder of all other commands, so no `-dir` is needed later.
- `init` refuses to overwrite: if `sdm/` exists, the project is already initialized; skip to `gen`.

Then set `<db url>` in `sdm/settings.xml` (the `<jdbc>` element is for the IDE plug-ins, sdmc ignores it):

| database   | `<db url="...">`                                            |
|------------|-------------------------------------------------------------|
| SQLite     | `sqlite:path/to/file.sqlite`, relative to the project root  |
| PostgreSQL | `postgres://host:5432/db`                                   |
| MySQL      | `mysql://host:3306/db`                                      |
| SQL Server | `sqlserver://host:1433;databaseName=db;encrypt=false`       |

User name goes to `user="..."`. Never write a password into `settings.xml`: pass it as `SDM_PWD`.

```bash
sdmc xml -orm no_orm > /tmp/sdm_gen.xml   # starting <dto-class>/<dao-class> for every table and view
```

Put the printed elements inside `<sdm>...</sdm>` of `sdm/sdm.xml`. Never redirect straight into
`sdm/sdm.xml`: the shell empties it before sdmc reads it. In Windows PowerShell 5.1 use
`| Out-File -Encoding utf8 file.xml` instead of `>` (it writes UTF-16, which sdmc does not read).

```bash
sdmc gen     # models -> internal/dbal/models, DAO -> internal/dbal; writes only what changed
sdmc val     # exit 1 if XML or schema changed since the last gen: use it to verify and in CI
```

Then make it run:

- `internal/dbal/data_store_<orm>_ex.go` is the user's part: the connection. It reads `DATABASE_URL`
  and has a default (`./app.sqlite3` for SQLite): set the default to the real database file or DSN.
- `internal/dbal/data_store_<orm>.go` is the engine. Do not change its adapter (`DS`, the `DataStore`
  interface, the `Set...` functions). `sdmc datastore` rewrites it as a whole after an sdmc update.
- `go mod tidy` pulls the driver. SQLite uses `github.com/mattn/go-sqlite3` (cgo, needs gcc); without
  cgo switch the import in `_ex` to `modernc.org/sqlite` and the driver name to `"sqlite"`.
- `go build ./... && go vet ./...`, then call the DAO from your code:

```go
ds := dbal.Ds()
if err := ds.Open(); err != nil { ... }
defer ds.Close()
list, err := dbal.GetProductsByCategory(ctx, 1)   // from <query-dto-list ... ref="Products(CategoryID)">
item, err := dbal.ReadProduct(ctx, 7)             // from <crud dto="Product" table="Products"/>
```

DAO functions are package-level `var` functions: tests replace them without interfaces or mocks.

## Changing the manifest

- A new table: `sdmc xml -orm no_orm` prints only what is not in `sdm.xml` yet; add it, `sdmc gen`.
- Own SQL: `<query-dto-list dto="X" method="getX(a, b)" ref="select ... where a=? and b=?"/>`
  (`<query-dto>` for one row), a scalar `<query method="countX(a)" ref="select count(*) ..."/>`
  (`<query-list>` for a column), DML `<exec-dml method="..." ref="update ..."/>`.
  A `ref` may also be a table with columns, `Products(CategoryID)`, or a file in `<folders sql>`.
  sdmc asks the database for the columns of the query, so the SQL must be valid for it.
- Where the driver says nothing about a type (SQLite and MySQL parameters, SQLite expressions such
  as `count(*)`), the Go type is `any`. Write the type in the XML instead:
  `method="countProducts(int64 categoryID)" return-type="int64"`, `method="getExpensive(float64 minPrice)"`.
- `<` and `>` in a `ref` are XML: write `&lt;` and `&gt;`.
- Model per class name: `Task` database/sql, `sqlx-Task` sqlx, `gorm-Task` gorm; the data store
  (`-orm` of init) must match.
- Several configurations (e.g. one per ORM) live in `.sdm` next to `go.mod`, a line `<dir>/go.dal` each;
  then `-c N` or `-c all` (`sdmc val -c all` in CI).
- `sdmc gen 1,3 TasksDao`, `-m` models only, `-d` DAO only; `sdmc ls -l` lists classes and files.

## Python and C++ (Qt)

```bash
sdmc init -lang python -dir sdm -dao dbal -db sqlite   # no go.mod needed, no -orm
sdmc init -lang cpp    -dir sdm -dao dal  -db sqlite
```

The rest is the same: `<db url>`, `sdmc xml` (no `-orm`), paste, `sdmc gen`, `sdmc val`. Python: a DAO
class over `create_ds(conn)` from `dbal/data_store_no_orm.py`, snake_case names. C++: headers
`<Class>.h` in `dal`, next to `DataStore.h`/`DataStore.cpp`.

## Checks before reporting done

1. `sdmc val` prints `up to date` (exit 0).
2. The project builds (`go build ./... && go vet ./...`, or imports for Python, compile for C++).
3. A real read through a generated DAO returns rows from the database. NULL columns become zero
   values; a type mismatch shows up as an error naming the column: fix the `<type-map>` in
   `settings.xml` (`<type detected="..." target="..."/>`), not the generated code.
